Bilingual Textbook Question-Answering System

Goal: Build an AI assistant where a student asks a question and the system answers first from the textbook itself, then gives a simple explanation and one or more examples. The system must support both Arabic and English books, because some student questions come from Arabic textbooks and others come from English textbooks.

Prepared on April 15, 2026. This report covers bilingual Arabic-English textbook QA, retrieval, explanation generation, model choices, public datasets, and fine-tuning.

1. Does This Require AI?

Yes. The full product is a combination of normal software and AI.

  • Normal software handles upload, storage, database, user accounts, interface, language routing, and logging.
  • AI handles semantic retrieval, question understanding, answer grounding, explanation generation, and example generation.

Best framing: This is not training a model from zero. It is usually a Retrieval-Augmented Generation (RAG) system built on top of pretrained Arabic-capable and English-capable models.

2. Bilingual Requirement: Arabic and English

Your final system should support two cases:

  1. Arabic question + Arabic textbook
  2. English question + English textbook

A stronger version can also support:

  1. Arabic question + English textbook
  2. English question + Arabic textbook

Recommended first scope: start with same-language retrieval first. That means Arabic questions search Arabic books, and English questions search English books. Cross-language retrieval can be added later if needed.

Recommended bilingual output policy

  • If the source book is Arabic, the quoted answer should stay in Arabic.
  • If the source book is English, the quoted answer should stay in English.
  • The explanation can follow the student's preferred language.
  • The final UI can include a language selector: Arabic, English, or same as source.

3. Recommended System Design

For your use case, the safest design is:

  1. Detect language of the question or use the chosen book language.
  2. Retrieve the relevant paragraph or section from the correct textbook collection.
  3. Extract the exact answer span or best supporting sentence from that passage.
  4. Generate a simple explanation and example using only that evidence.

Why this order matters: If the model explains first without grounding itself in the book, it may hallucinate. For educational use, a quote-first, explain-second pipeline is much safer.

Output format

  1. From the book: exact quote or faithful extract
  2. Explanation: simpler explanation in Arabic or English
  3. Example: one short example
  4. Source: chapter, section, page

4. Technical Architecture

ModuleRole

Flow

Arabic/English question -> language routing -> retrieval -> evidence selection -> answer generation -> grounded response

5. Language-Specific Challenges

  • Arabic normalization: diacritics, alef variants, ta marbuta, ya/alef maqsura, punctuation.
  • Arabic PDF extraction quality: Arabic PDFs can have line-order and shaping issues.
  • English textbook structure: tables, captions, formulas, and side-notes may affect chunking.
  • Mixed-language education: a student may ask in Arabic about an English book or vice versa.
  • Terminology mismatch: scientific terms may appear in English inside Arabic questions.

6. Best Build Strategy

Phase 1: Build a bilingual RAG system with pretrained models. Do not train a base model from scratch.

Phase 2: If needed, fine-tune either:

  • a bilingual retriever for textbook search,
  • an extractive QA model for exact answer spans,
  • or an instruction/generation model for better explanations.

This means your system can first find the passage, then extract the answer, then explain it.

8. Can You Train a New Model?

Yes, but there are three different meanings of train:

  1. Use pretrained model only: no new training, only prompting and retrieval.
  2. Fine-tune a pretrained model: most realistic for a student project.
  3. Pretrain a brand-new model from scratch: usually too expensive and unnecessary.

For your project, fine-tuning pretrained models is the right path if the basic RAG system is not enough.

9.3 If you cannot collect data from your own books

That is completely workable. You can start with public internet datasets for Arabic and English, then later test on your book collection through RAG.

  • Arabic QA datasets: ARCD, Arabic-SQuAD, TyDi QA Arabic, MLQA Arabic, XQuAD Arabic.
  • English QA datasets: SQuAD, Natural Questions, HotpotQA, RACE, NarrativeQA.
  • Multilingual QA datasets: TyDi QA, MLQA, XQuAD, XOR QA.
  • Retrieval datasets: MS MARCO for English warm-start, multilingual retrieval benchmarks, BEIR-style tasks where available.

Important limitation: public internet datasets are useful for fine-tuning general question answering, but they are not the same as your exact textbook domain. So the best plan is to use public data for warm-start training and rely on RAG over your actual books during inference.

10. Fine-Tuning Plan

10.1 Fine-tuning the retriever

Goal: retrieve the correct Arabic or English textbook paragraph.

  1. Build question-passage pairs from public QA datasets and any accessible educational text.
  2. For each question, mark one correct paragraph and several hard negatives.
  3. Train a bi-encoder using contrastive loss.
  4. Evaluate with Recall@k and MRR.

10.2 Fine-tuning the extractive QA model

Goal: return the literal answer from the source passage.

  1. Format Arabic and English context-question pairs.
  2. Mark exact answer spans inside the context.
  3. Fine-tune Arabic and English span-extraction models, or use one multilingual model.
  4. Evaluate with Exact Match and F1.

10.3 Fine-tuning the generator

Goal: produce a simple explanation and an example in Arabic or English.

  1. Create supervised examples where input includes the question and evidence passage.
  2. Output should follow your final template: quote, explanation, example, source.
  3. Fine-tune a sequence-to-sequence model such as AraT5 or mT5, or use parameter-efficient tuning on a multilingual LLM.
  4. Evaluate for grounding, clarity, and hallucination rate.

11. Step-by-Step Fine-Tuning Workflow

  1. Collect data: gather public Arabic and English QA datasets from the internet.
  2. Clean and normalize: Arabic normalization plus English cleanup and consistent punctuation.
  3. Prepare retrieval pairs: generate positives and hard negatives.
  4. Prepare QA labels: exact answer spans for Arabic and English.
  5. Prepare generation labels: target answer with explanation and example.
  6. Split the dataset: train, validation, test with no leakage.
  7. Choose the training target: retriever, reader, generator, or all three.
  8. Start with the retriever: retrieval quality usually determines overall system quality.
  9. Then fine-tune extractive QA for exact textbook-style answers.
  10. Then adapt the generator for teaching-style explanations.
  11. Run grounded evaluation: check citation correctness and unsupported claims.
  12. Deploy and log: save failed questions to improve the next version.

13. How Long Does Training Take?

The answer depends on model size, dataset size, hardware, and whether you are fine-tuning the full model or using LoRA / parameter-efficient tuning.

Training targetTypical setupEstimated time
Embedding retriever fine-tuningSmall to medium bi-encoder on 1 GPU2 to 8 hours
Arabic or English extractive QA fine-tuningBERT-size model on 1 GPU1 to 6 hours
Multilingual extractive QA fine-tuningmBERT / XLM-R size on 1 GPU4 to 12 hours
Small seq2seq explanation modelmT5-small/base or AraT5-like model on 1 GPU4 to 16 hours
LoRA fine-tuning of a larger LLM7B-class model on strong GPU6 to 24 hours
Training from scratchLarge-scale pretrainingweeks to months

Realistic recommendation for a graduation project: plan for days, not months, by using pretrained models and fine-tuning only the necessary components. Full pretraining from scratch is not realistic unless you have major compute resources.

Practical estimate: if you fine-tune a retriever, an Arabic QA model, and an English QA model on a normal research GPU, the full experimental cycle may take roughly 2 to 7 days including preprocessing, training, validation, reruns, and debugging.

16. Best Final Recommendation for Your Project

  1. Start with a bilingual RAG pipeline using pretrained models.
  2. Use multilingual embeddings so Arabic and English are both supported.
  3. Keep the output strictly structured: quote, explanation, example, source.
  4. Use public internet datasets first, because you cannot annotate your own books right now.
  5. Fine-tune the retriever first, because retrieval quality is critical.
  6. Fine-tune Arabic and English extractive QA models if you need exact source spans.
  7. Fine-tune the generator last for educational explanation style.

17. Suggested Project Roadmap

  1. Collect Arabic and English textbooks.
  2. Extract and clean text.
  3. Build chunking plus metadata pipeline with a language field.
  4. Store multilingual embeddings in Chroma or FAISS.
  5. Implement language routing and grounded answering.
  6. Download public Arabic and English QA datasets from the internet.
  7. Prepare a bilingual evaluation set.
  8. Measure retrieval quality and answer groundedness.
  9. Fine-tune components if needed.
